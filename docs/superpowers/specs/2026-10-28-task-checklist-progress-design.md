# 任務列 checklist 子項目（第一階段）設計

日期：2026-10-28
狀態：草稿（待使用者核可）

## 為什麼

使用者想要「子任務」。市場調查（見對話紀錄）的結論：需求真實存在，但最大的痛點是「子項目在清單上看不到」（Apple Reminders 被罵最多的點），而不是「沒有巢狀任務」。Nudge 已經有子項目的雛形：任務內文（`tasks.description`）可以用 `/` 插入待辦列表（tiptap `taskList` / `taskItem`），只是這些項目只在任務詳情裡看得到。

所以採用「方案 A」：**不新增資料模型，子項目 = 任務內文裡的待辦項目**，把它們拉到今日清單的任務列上，顯示進度、可直接勾選與新增。

## 目標

1. 任務列外層顯示子項目進度 `已勾/總數 ▾`（例：`2/5 ▾`）。
2. 子項目在任務列下方列出，**預設展開**；使用者可手動收合，**收合後不會自己展開**。
3. 在清單上直接勾選子項目。
4. 在清單上新增子項目。
5. 母任務與子項目**雙向同步**：子項目全勾 → 母任務完成；勾母任務 → 子項目全勾；母任務完成後取消任一子項目 → 母任務變回未完成。
6. Web、macOS、iOS 三邊行為一致。

## 非目標（第一階段不做）

- **重複任務**：有重複規則的任務，第一階段**完全不顯示**子項目進度與清單、不自動完成，`···` 選單也不出現「新增子項目」。原因：內文是整條規則共用的，勾選狀態沒辦法每天重置（見「第二階段」）。
- 在清單上編輯或刪除子項目文字、拖曳排序子項目（要改請進任務詳情）。
- 子項目有自己的日期、提醒、標籤。
- 卡片頁（`/cards`）的卡片外觀不變。
- 收合狀態跨裝置同步。

## 反目標（做了等於失敗）

- 沒有待辦列表的任務外觀**有任何改變**。
- 在清單上勾選／新增後，任務詳情裡看到的內容不一致，或把使用者在另一台裝置剛寫的內文蓋掉。
- 讀取或改寫內文時弄壞內文裡的其他內容（段落、圖片、標題、其他格式）。

## 已定案的設計（使用者決定）

### 版面（使用者選 mockup「A」）

```
[☐] 準備週會簡報                       2/5 ▾   ···
      [☑] 整理上週數據
      [☑] 更新 OKR 進度
      [☐] 做三張圖表
      [☐] 寫結論
      [☐] 寄給 PM 預覽
      ＋ 新增子項目
```

- 進度膠囊 `2/5 ▾` 放在任務列右側、`···` 左邊；整顆可點，切換收合／展開；收合時箭頭轉向右（`▸`）。
- 全部勾完時數字變主色（`primary` token）。
- 子項目縮排，左緣對齊母任務標題；勾選框比母任務小（mockup：14px vs 18px），字級小一號；已勾項目刪除線 + `text-dim`。
- 子項目只顯示**純文字**（內文裡的粗體、連結等格式拿掉）。只列待辦項目，內文其他段落、標題、圖片都不出現在清單上。
- 內文中有多個待辦列表時，依出現順序合併成一份。
- 沒有任何待辦項目的任務：不顯示膠囊、不顯示子項目區，外觀與現在完全相同。

Mockup 檔案：`.superpowers/brainstorm/4074-1793169767/content/subtask-row.html`、`add-subtask.html`（本機，未進 git）。

### 新增子項目（使用者選「選單」）

- **還沒有子項目的任務**：任務列 `···` 選單（Web 的 dropdown + 右鍵選單、Mac/iOS 的 `TaskRowMenu`）新增一項「＋ 新增子項目」。點了 → 任務展開，子項目區出現輸入框並自動聚焦。三個平台都走選單，不做 hover ＋ 按鈕。
- **已有子項目的任務**：展開狀態下，子項目最下方固定一行「＋ 新增子項目」，點了變輸入框。
- 輸入框：Enter → 新增並清空、繼續輸入下一個；Esc 或失焦 → 結束。空字串 Enter 不新增。失焦時若還沒新增任何項目，輸入框消失、任務回到原本樣子。
- 新增的項目寫在內文中**最後一個待辦項目之後**；內文沒有待辦項目則加在內文最後。

### 母任務 ↔ 子項目雙向同步（使用者決定）

只對「有至少 1 個子項目的非重複任務」生效。規則只看**轉變**，不看靜態狀態：

| 發生什麼 | 結果 |
|---|---|
| 子項目從「未全勾」變成「全勾」 | 母任務自動完成（等同使用者勾了母任務：移到「已完成」區、走既有完成流程） |
| 子項目從「全勾」變成「未全勾」，且母任務目前已完成 | 母任務自動變回未完成 |
| 使用者勾選母任務為完成 | 所有子項目全部勾上（改寫內文） |
| 使用者取消母任務完成 | **子項目維持原樣**（Claude 的預設，使用者未反對） |

- **適用的操作位置**：今日清單上勾子項目／勾母任務，**以及在任務詳情視窗的內文裡勾子項目**（使用者確認詳情也要同步）。
- 詳情裡的判斷方式：每次存檔時比較存檔前後內文的「是否全勾」，跨過全勾這條線就套用上表。不需要在編輯器裡攔截勾選框點擊，三個平台都不用改編輯器 bundle。
- **已知且接受的副作用**：在詳情裡刪掉最後一個未勾項目、把未勾項目改成一般段落，也會被視為「變成全勾」而自動完成母任務。
- **不會觸發的情況**：載入內容時剛好全勾；收到其他裝置即時同步而重載內容（不是本機存檔）；新增子項目讓「全勾」變成「未全勾」時，**不**把已完成的母任務拉回未完成（新增視為新工作，不是撤銷）。

## 我（Claude）替使用者做的決定 — 請核對

1. **取消母任務完成時子項目不動**（見上表；已在對話中說明，使用者未反對）。
2. **新增子項目不會把已完成的母任務拉回未完成**（見上方「不會觸發的情況」）。
3. **同步的觸發範圍限今日清單脈絡**：今日清單，以及從今日清單（含「前幾天的」區）打開的任務詳情。從卡片頁打開的詳情沒有「哪一天」的脈絡，不觸發母任務狀態變更。
4. **「已完成」區的任務**：子項目區預設不展開、只顯示膠囊（例 `5/5 ▸`），點膠囊可展開。這不寫入收合記憶。理由：自動完成後整串全勾的子項目留在已完成區太佔空間。
5. **收合記憶**：每台裝置各自記住，以 task id 為 key（Web：`localStorage`；Apple：`UserDefaults`）；沒有紀錄 = 展開。
6. **點子項目整行就切換勾選**（不只點框框），跟 mockup 一致；點子項目不會打開任務詳情。
7. 「前幾天的」（overdue）區的任務也套用同樣的子項目顯示。

## 技術約束與方向

### 資料

- 不改 schema、不加 migration。子項目完全由 `tasks.description` 的 HTML 推導。
- `GET /api/daily/[date]` 已經回傳 `description`，不需要新 API。
- 寫入走既有 `PATCH /api/tasks/[id]`，帶 `description` + `baseUpdatedAt`（樂觀並行，衝突回 409 + 最新 task）。

### 內文 HTML 結構

- 編輯器設定 `TaskItem.configure({ nested: false })`，不會巢狀。
- **兩種結構都會出現**：Web 編輯器有 `SplitTaskList`（每個 `taskList` 只含一個 `taskItem`），但 Apple bundle 暫時停用了它（`apple/NudgeEditor/src/main.ts`，為了隔離 iOS 輸入 bug），onboarding 範例內文也是一個 `<ul>` 多個 `<li>`。解析必須同時支援「一 ul 一 li」與「一 ul 多 li」，共用測試案例兩種都要涵蓋。
- **（Claude 的決定）新增項目的插入位置**：插在最後一個 `taskItem` 的 `</li>` 之後、同一個 `<ul>` 內。這對兩種結構都合法；Web 編輯器載入時 `SplitTaskList` 會自動拆開。內文沒有任何待辦項目時，在內文最後新增一個 `<ul data-type="taskList">` 包一個 `<li>`。
- 待辦項目序列化形如 `<ul data-type="taskList"><li data-checked="true|false" data-type="taskItem">…<div><p>文字</p></div></li></ul>`。**實作前請用 `@tiptap/html` 對目前版本（3.32）產生一次真實輸出確認屬性順序與包裝**，新增項目時要產出跟編輯器一致的 HTML，否則 Apple bundle / Web 編輯器重新存檔時會出現無意義 diff。

### 純邏輯模組（兩份鏡像，比照 `live-sync-rules.ts` ↔ `RemoteChangeDecision.swift`）

- Web：`src/lib/checklist.ts`（新檔）＋ `checklist.test.ts`。
- Apple：`NudgeCore/ChecklistHTML.swift`（新檔）＋ 測試。Apple 任務列是原生 SwiftUI，不經 webview，所以 Swift 端要自己解析／改寫 HTML（可參考 `AttachmentHTMLRewrite.swift` 的做法）。
- 功能：
  - `parse(html) → [{ text, checked }]`（依文件順序；文字為去格式純文字）
  - `toggle(html, index, checked) → html`
  - `append(html, text) → html`（文字要做 HTML escape）
  - 只改動目標 `taskItem` 的 `data-checked` 或插入新節點，**其餘位元組保持原樣**。
- 兩邊共用同一組測試案例（同樣的輸入 HTML / 預期輸出）。

### 子項目識別與衝突處理

- 子項目以「在內文中的順序 index」識別。
- 寫入是「意圖型」：toggle 記 `(index, 該項文字, 目標 checked)`；append 記 `text`。
- 收到 409 → 拿 server 回的最新 description 重新套用意圖：toggle 時若最新內文的第 index 項文字與當初相同才套用，否則放棄並以最新內容刷新畫面；append 一律可套用。
- 套用後的狀態以 server 回應為準（避免樂觀更新與實際不一致）。

### 與即時同步的互動

- 在清單上改內文會觸發既有的 `notifyUserDevices(kind:"task")`，其他裝置打開中的編輯器會依既有 `live-sync-rules` 判斷是否重載。不另外設計。
- **（使用者決定）同一裝置詳情正開著同一個任務時，編輯器是唯一寫入者**：主要情境是 Mac 右欄詳情與左側清單並存。清單上的勾選／新增不自己存檔，改為通知開著的編輯器：編輯器先 flush 自己未存的內容 → 把這次操作（toggle / append / checkAll）套進自己的內文 → 由它存檔 → 重新載入顯示（`reloadToken` 重建，捲動位置回頂端可接受；使用者此時焦點在清單，不在打字）。詳情沒開這個任務時，清單照常自己存。
  - 原因：清單自己存會推進共用的版本基準，SSE 回音因同一秒被當成自己的回音略過，編輯器不會重載；它下一次 debounce 存檔又因基準已推進而不會被 409 擋，會用舊內容蓋掉清單的修改。

### 平台位置

- Web：`src/components/task/task-card.tsx`（任務列）、`src/components/daily/daily-view.tsx`、`overdue-section.tsx`。
- Apple（iOS + macOS 共用 NudgeUI）：`Daily/TaskRowView.swift`、`TaskRowMenu.swift`、`TaskListView.swift`、`OverdueSectionView.swift`；寫入走 `TaskRepository.updateDescription`。
- 依 AGENTS.md：顏色只用 design token（Web Tailwind token / Swift `Color.nudgeXxx`）；Apple checkbox 用 `NudgeCheckbox`；icon-only 按鈕用 `IconButton`。

### i18n

新 key 先加 `i18n/canonical/zh-TW.json` → `npm run i18n:sync`（en/ja 翻譯）→ 鏡像到 `Localizable.xcstrings`。至少需要：
- 選單／底部列「新增子項目」
- 輸入框 placeholder
- 膠囊的 a11y label（例「已完成 {done}/{total} 個子項目，點擊收合／展開」）
- 子項目勾選框 a11y label

## 第二階段（不在本文件範圍，僅記錄方向）

重複任務的子項目每天重置：內文當「範本」，每日勾選狀態另存在 `daily_task_assignments`（新增 nullable 欄位）；子項目需要穩定 ID（不能只靠 index）；任務詳情要依當天狀態顯示勾選。屆時另寫設計。
